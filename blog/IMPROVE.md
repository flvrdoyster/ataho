# 블로그 스킨 개선 사항 리스트

oysterbay.tistory.com 의 티스토리 스킨(`skin.html` + `skin.css` + `images/`).
남은 과제만 정리. 완료되어 제외된 항목은 git 히스토리 참조.

파일을 고쳐도 블로그에 자동 반영되지 않는다 — 티스토리 관리자 → 스킨 편집에
`skin.html` 은 HTML 탭, `skin.css` 는 CSS 탭에 붙여넣어야 적용된다.
`preview.html` 은 그 전에 로컬에서 눈으로 확인하는 용도(실제 스킨엔 포함 안 됨).

## 1. 글 목록 요약의 문단 경계가 사라진다 — 스킨에서 해결 불가
목록 카드의 `[##_article_rep_summary_##]` 가 원문의 문단 경계를 지우면서
**공백을 하나도 넣지 않는다.** 그래서 "신 컴파일 소식지최강 마지막!?" 처럼
앞뒤 문장이 그대로 붙어 읽힌다.

확인해 본 결과(2026-08-26) 문제 지점의 문자 코드가 `지(51648)` → `최(52572)` 로,
개행·공백·NBSP·탭 중 **아무것도 없고** 텍스트 노드도 1개다. 즉 정보가 스킨에
도달하기 전에 소실된다 — `white-space: pre-line` 같은 CSS 는 작용할 대상이 없고,
JS 로도 복원이 안 된다(문장부호가 있는 `!이번` 은 규칙으로 끼울 수 있지만
`소식지최강` 은 단서가 없다).

남은 선택지 셋. 아직 고르지 않았다.
- 글쓰기 쪽에서 회피 — 첫 문단을 요약으로 그대로 써도 되는 완결된 문장으로 시작.
  새 글부터만 듣는다.
- 목록에서 요약을 빼거나 줄이고 제목·썸네일 중심으로. 문제는 없어지지만 정보도 준다.
- `[##_article_rep_desc_##]`(본문 전체)를 목록에 넣고 CSS 로 잘라내기. 문단 구조는
  살지만 목록에서 본문 HTML·이미지를 통째로 불러오게 돼 무겁고, 목록 컨텍스트에서
  이 치환자가 동작하는지부터 확인해야 한다.

## 2. 한자가 폰트 폴백으로 빠진다 — 그대로 두기로 함
본문 서체 `--font-ui`(KoddiUDOnGothic)에 **한자 글리프가 없다.** 한글·영문·가나는
있고 한자만 OS 기본 CJK 폰트로 넘어가서, `DSアニメ総集編'98` 같은 제목은 한 줄
안에서 한글은 가늘고 한자만 굵게 보인다. 보는 OS 마다 한자 모양도 달라진다.

전에 쓰던 Pretendard 로 같은 문장을 렌더해도 결과가 거의 동일했다 — **서체를
바꿔서 생긴 문제가 아니라 둘 다 한자가 없어서** 원래부터 그랬다. 이 블로그는
환세 시리즈 원제·일본어 인용이 많아 눈에 띄는 편이지만, 2026-08-26 논의에서
그대로 두기로 했다. 나중에 손본다면:
- 폰트 스택 뒤에 일본어 웹폰트(예: Noto Sans JP)를 명시 → OS 별 편차만 없앤다.
  한글(온고딕)과 한자(Noto)의 인상 차이는 남는다.
- 본문 전체를 한자까지 있는 범CJK 폰트로 → 한 줄이 균일해지지만 사이트 공통
  서체에서 블로그만 이탈한다.
둘 다 `--font-ui` 가 공유 토큰(`/design-tokens.css`)이라, 다른 서브프로젝트까지
바꿀지 블로그에서만 덮어쓸지 함께 정해야 한다.

## 3. preview.html 의 일부 블록은 추정 마크업이다
`preview.html` 의 샘플 중 **이미지 블록만** 실제 발행 글(#134)에서 확인한 구조다.
**파일첨부·인용구·동영상**은 이 블로그에 해당 블록을 쓴 글이 아직 없어서, `skin.css`
선택자만 보고 역추정한 마크업이다(페이지에 회색 안내 박스로 표시해 뒀다).

셋 중 하나라도 실제로 쓴 글이 생기면 그 글에서 진짜 마크업을 뽑아 preview 를
맞춰야 한다. 특히 파일첨부는 예전에 추정 마크업이 틀려서(`.filename` 을 `span`
으로 썼는데 실제 CSS 는 블록 요소 전제) 레이아웃이 깨져 보인 적이 있다.

## 4. 이미지 스프라이트 의존이 댓글 위젯에만 남아 있다
스킨이 직접 그리는 아이콘은 전부 인라인 SVG(`.ico`)로 옮겼고, 굵기는
`--ui-border-w`(상자선) / `--ico-stroke-w`(글자획) 두 토큰이 관리한다.

다만 `images/ico_skin*.{gif,png}` 는 아직 지울 수 없다 — 댓글 위젯의 아이콘
(답글 화살표, 비밀글 자물쇠, 체크박스, 더보기 점 세 개)이 그 스프라이트를 쓴다.
이 마크업은 `skin.html` 에 없고 티스토리가 런타임에 넣기 때문에, 실제 댓글이
있는 글에서 마크업을 확인해야 인라인 SVG 로 옮길 수 있다.

새 아이콘을 추가할 때는 **viewBox 를 표시 크기와 1:1 로** 맞출 것. 어긋나면
user unit 과 px 이 달라져 아이콘마다 선 굵기가 다시 갈린다(`skin.css` 의 `.ico`
주석 참고).

## 5. 작품별 태그 내비게이션(`.area_titlenav`) — 새 작품이 생기면 수동으로 추가
2026-08-26에 확인한 바로 카테고리는 "환세 시리즈 연구" 하나뿐이라 사실상
죽어 있고(전체/카테고리 필터 결과가 항상 같음), 실제 목차 구실은 태그가 한다
(글마다 `환세취호전`처럼 작품 태그가 정확히 붙음). 그래서 헤더 바로 아래에
작품 6개를 pill 링크로 박아 넣었다(`skin.html` 의 `.area_titlenav`, `/tag/작품명`
— 티스토리가 기본 제공하는 페이지라 서버 쪽엔 새로 만든 게 없음).

**티스토리 skin.html엔 조건부 merge tag가 없어서 이 목록은 하드코딩이다.**
지금은 "이 6개가 전부"(2026-08-26 확인)라 문제 없지만, 새 작품 글을 시작하면
`skin.html` 의 `.area_titlenav` 블록에 `<a href="/tag/새작품">새작품</a>` 한 줄을
직접 추가해야 한다 — 자동으로 안 늘어난다. `환세시리즈`/`환세 시리즈`처럼
띄어쓰기만 다른 중복 태그가 있는 건 확인했지만 태그 정리는 글쓰기 쪽 작업이라
스킨에서는 손대지 않았다.

## 7. 좋은 블로그 디자인 레퍼런스에서 가져올 것들 — 논의만 하고 미착수
2026-08-27, joshwcomeau.com·gwern.net(개별 글 페이지)을 실제로 열어보고 참고할
점을 뽑았다. 우선순위 순:
- **글 제목 밑에도 태그 칩** — 지금은 글 맨 아래(다 읽은 후)에만 있음. gwern은
  제목 바로 밑에 태그를 놔서 읽기 전에 "무슨 글인지" 알 수 있게 함. 오늘 만든
  `.area_titlenav`/`.desc_tag a` 포인트색 스타일을 그대로 재사용하면 됨.
- **본문 첫 문단 드롭캡** — `::first-letter`, 리스크 없는 CSS. 장문 번역 아카이브
  라는 "출판물" 느낌을 강화.
- **제목/본문 크기 대비를 더 벌리기** — 지금 위계가 약한 편.
- **목록 썸네일 방향이 미정** — 예전 제안(2026-08-26)은 "썸네일을 더 키우자"였는데,
  joshwcomeau.com 목록은 썸네일이 아예 없고 타이포그래피만으로 승부함. 정반대
  방향이라 둘 중 하나를 골라야 함(스캔 이미지가 콘텐츠의 절반인 이 블로그 특성상
  썸네일 방향이 더 맞을 수도 있음 — 확정 아님).

## 8. 헤더·푸터에 귀여운 호버 인터랙션 — 확인만 하고 미착수
2026-08-27, joshwcomeau.com에서 확인: 로고 옆 작은 스파클이 hover 시 벌어지듯
움직이고, 푸터의 캐릭터 아바타는 hover 시 다른 모자(바이킹 투구 등)를 씌운
모습으로 바뀜.

- **새 그림 없이 CSS만으로 가능한 것**: 헤더 프로필 사진(맛굴) hover 시 씰룩
  흔들리는 애니메이션, 작품 태그 칩 hover 시 통통 튀는 효과, 푸터에 같은
  프로필 사진을 작게 재사용해 hover 흔들림 추가.
- **새 그림이 필요한 것**: 모자 바꿔쓰기 같은 "의상 스왑" 이스터에그 — 맛굴
  캐릭터의 다른 표정/의상 버전 이미지가 없어서, 새로 그리거나(그림체 맞추기
  까다로움) 만들어 주셔야 진행 가능.

CSS만으로 되는 것부터 갈지, 그림이 필요한 것도 같이 갈지 아직 안 정했다.

## 9. 사이드바 구성은 손대지 않았다
데스크탑 하단 사이드바(`.wrap_etc`)에 공지사항·최근 글·최근 댓글·방문자수·링크·
태그·달력·글 보관함 8종이 정의돼 있고, 모바일에서는 통째로 숨는다. 항목이 없는
목록형 위젯은 자동으로 숨도록 처리했지만(`:has()`), **어떤 위젯을 남길지는
정하지 않았다.** 개인 블로그 기준으로는 과한 편이라 최근 글·태그 정도로
줄이는 안을 2026-08-26에 제안만 해 둔 상태다.
