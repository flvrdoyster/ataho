# 티스토리 블로그 지표 연결 — 설정 순서

목표: `oysterbay.tistory.com`의 방문 지표를 **기존 사이트와 완전히 분리된**
GA4 속성에 쌓고, 대시보드에 "블로그" 탭으로 붙인다.

분리해서 쌓는 이유 — 같은 속성에 넣으면 블로그가 "내 사이트"로 취급돼
합계 사용자·세션·참여율에 늘 섞이고, 지금 유입 2위로 잡히는
`oysterbay.tistory.com → atah.io` referral 집계도 교차 도메인 설정에 따라
달라진다. 속성을 나누면 기존 사이트 숫자는 손대지 않은 채 그대로 남는다.

아래 1~5는 구글/티스토리 계정 권한이 필요해 직접 하셔야 한다.
6번부터가 이쪽 작업이다.

---

## 1. GA4 새 속성 만들기

Google Analytics → 관리(좌하단 톱니) → 속성 열의 **속성 만들기**

- 속성 이름: 예) `oysterbay 블로그`
- **보고 시간대: 대한민국 (GMT+09:00)** — 기존 속성과 맞춰야 히트맵의
  "몇 시에 몰리는가"가 두 탭에서 같은 기준이 된다. 나중에 바꿔도 과거
  데이터는 소급 적용되지 않으니 지금 맞춰 둘 것.
- 통화: 대한민국 원

## 2. 웹 데이터 스트림 추가

속성을 만들면 이어서 데이터 스트림을 묻는다. **웹**을 고르고

- 웹사이트 URL: `https://oysterbay.tistory.com`
- 만들고 나면 **측정 ID `G-XXXXXXXXXX`** 가 나온다 → 4번에서 쓴다

## 3. 서비스 계정에 뷰어 권한 주기

관리 → **속성 액세스 관리** → 사용자 추가

```
ga-reader@atah-io.iam.gserviceaccount.com
```

- 역할: **뷰어** (읽기만 하면 된다)
- 알림 메일 보내기는 꺼도 된다 — 서비스 계정이라 받을 사람이 없다

기존 속성(`516513119`)에 이미 쓰고 있는 것과 같은 계정이다. 이걸
빠뜨리면 수집 스크립트가 새 속성에서 403을 받는다.

## 4. GTM 컨테이너는 **새로** 만들기

tagmanager.google.com → 컨테이너 만들기

- 이름: `oysterbay.tistory.com`, 타겟 플랫폼: **웹**
- 컨테이너 안에서 태그 하나 추가 — 유형은 **Google 태그**,
  태그 ID에 2번의 측정 ID(`G-`로 시작), 트리거는 모든 페이지
- **제출 → 게시**까지 해야 실제로 동작한다. 저장만 하면 반영 안 됨

> 기존 `GTM-PR4S897C`를 재사용하지 말 것. 재사용하려면 태그마다
> hostname 트리거 조건을 걸어야 하는데, **기존 GA4 태그 쪽 조건을
> 빠뜨리면 블로그 데이터가 기존 속성에도 같이 들어간다.** 분리하려는
> 것과 정반대 결과라, 컨테이너를 나누는 편이 실수할 여지가 없다.

## 5. 티스토리에 스니펫 넣기

티스토리 관리 → 꾸미기 → **스킨 편집 → html 편집**

- `<head>` 여는 태그 **바로 뒤**에 첫 번째 스니펫
- `<body>` 여는 태그 **바로 뒤**에 두 번째(`<noscript>`) 스니펫
- 적용

주의할 점 둘:

- **스킨을 바꾸면 이 HTML 편집 내용이 날아간다.** 나중에 스킨을 교체할
  일이 있으면 넣은 스니펫을 따로 복사해 두고 교체 후 다시 넣어야 한다.
  (서치콘솔·애드센스 코드도 같이 날아가니 함께 백업)
- 모바일 웹에 별도 스킨을 쓰고 있다면 그쪽에도 넣어야 모바일 방문이 잡힌다.

### 확인

GA4 → 보고서 → **실시간**에서 본인 방문이 잡히면 성공이다.
반영까지 몇 분 걸릴 수 있다.

## 7. 파이프라인 — 붙임

- `scripts/ga4_dashboard.py`가 속성 여러 개를 돈다(`Target`). 대상마다
  `dashboard/data/<key>.js` 하나. 블로그는 `GA4_BLOG_PROPERTY_ID`가
  있을 때만 수집한다 — 없으면 조용히 건너뛴다.
- 워크플로우가 `dashboard/data/` 전체를 커밋한다. 속성 ID는 시크릿이
  아니라 env로 뒀다 — 공개돼도 서비스 계정 권한 없이는 못 읽는다.
- 탭은 `dashboard.js`가 데이터 파일 개수만큼 자동 생성한다. 대상을 더
  늘리려면 수집 스크립트에 `Target` 추가 + `index.html`에 `<script>` 한 줄.
- 블로그 화면은 사이트와 다르게 나온다: 호스트가 하나뿐이라 **사이트별·
  코너별은 빠지고**, 인기 목록이 경로 대신 **글 제목(pageTitle)** 기준이다.

## 8. 남은 확인

측정 코드가 실제로 발화하는지는 아직 확인되지 않았다. 실시간 조회 결과
블로그 속성 활성 사용자 0 — 최근 30분간 방문이 없어서일 수도, 4·5번이
덜 끝나서일 수도 있다. 블로그를 한 번 열고 GA4 → 보고서 → 실시간에
잡히는지 보면 갈린다.

수치가 채워지는 건 그 다음 날부터다. 추세선과 "지난 7일 대비"는 하루치가
쌓여야 의미를 갖는다. 그전까지 블로그 탭은 "아직 집계된 하루가 없습니다"만
보여준다.
