# 대시보드 개선 사항 리스트

남은 과제만 정리. 완료되어 제외된 항목은 git 히스토리 참조.

## 0. 게임 스타일 입히기 — 다음 차례
밑작업은 끝났다(2026-08-10 시작, 2026-08-14 박스 개편으로 갱신). 보이는 값은
전부 `dashboard/theme.css` 의 토큰 한 곳에 있고, `dashboard.css`(구조)와
`dashboard.js`(차트)는 그 값을 읽기만 한다 — 색·서체 리터럴이 두 파일에
남아 있지 않다(검증: 토큰 61개 전부 정의·사용됨, 미정의 참조 0 / 미사용 0).

실제로 입힐 때 손볼 자리는 theme.css 머리 주석에 적어 뒀다. 요지만:
- `--font-ui` 를 Dokkaebi DNR Gothic 으로. 이때 `--fs-*` 를 rem 소수에서
  정수 px 로 바꿔야 한다 — 도트 서체는 16의 배수가 아닌 크기에서 획이 뭉갠다.
  그러라고 글자 크기를 8개 토큰으로 모아 뒀다.
- `--img-rendering: pixelated`, `--radius-*` 와 `--panel-radius` 를 0 으로
- 9-슬라이스 프레임은 토큰만으론 안 되고 `.module` 규칙 하나가 더 필요하다
  (world/ui.css 의 `.frame-box` 와 같은 방식, theme.css 주석에 4줄로 적힘).
  박스 개편(2026-08-14) 이후 화면 자체가 박스 단위라 이 스킨과 잘 맞는다.
- 차트 기하(`--line-tension`, `--point-r`, `--strip-cell` 등)도 토큰이라
  픽셀 톤에 맞춰 각지게 바꿀 수 있다.

## 1. GA와의 차별점 — 많이 좁혔다
2026-08-14 개편으로 GA 기본 화면과 갈라지는 축이 하나 생겼다. **어제 하루를
주어로 삼고, 지표마다 GA4의 확정 시점이 다르다는 걸 화면이 알고 있다는 점**이다
(참여율·채널은 어제 칸에서 빼고 확정 구간에서만 보여준다). GA는 이 구분을
해 주지 않아서, 어제 참여율 0%를 그냥 0%로 보여준다.

2026-08-18에 하나 더 붙였다 — **히스토리("살아있는 기록")**. 히어로의 ◀▶로
최근 28일 아무 날짜나 다시 볼 수 있고, 그중 그저께치는 GA4 재처리가 끝난
값으로 매일 자동 갱신된다(`scripts/ga4_dashboard.py`의 `HISTORY_REFRESH_AGE`).
GA는 "그 날짜가 지금은 얼마로 확정됐는지"를 알아서 다시 보여주지 않는다 —
사람이 직접 같은 날짜를 다시 조회해야 한다. 이건 원래 유입원 미분류 문구가
"내일이면 채워집니다"라고 써 놓고 실제로는 이 페이지 안에서 확인할 길이
없었던 문제를 고치다가 나온 결론이다: 문구만 고치는 대신 기능으로 그 약속을
실제로 지키게 만들었다.

남은 차별점 후보는 여전히 **GA가 구조적으로 알 수 없는 것**이다. GA는 이 레포를
모른다 — 언제 무엇을 만들었는지 알 방법이 없다(`/sweep`이 미니게임인 건
코너 분류로 이미 화면에 들어갔다). 후보(검토만 하고 보류):
- **커밋 × 방문 겹쳐 보기** — 추세선에 그날의 커밋을 표시해 "뭘 만들었더니
  사람이 어떻게 움직였나"를 보여준다. `git log`만 있으면 되고 구현이 가볍다.
- **미니게임 이벤트 계측** — 시작·클리어·이탈을 GA4 커스텀 이벤트로 심고
  게임별 완주율을 본다. 가장 값지지만 각 게임에 코드 삽입이 필요하다.

검토 후 **접은** 후보 둘(2026-08-10):
- **인구통계(연령·성별)** — 못 쓴다. 이 속성에 직접 물어보니 `userAgeBracket`·
  `userGender`·`brandingInterest` 세 차원 모두 rowCount 0, 완전히 빈 응답이다.
  Google 신호 데이터가 꺼져 있거나 트래픽이 임계값 아래라서인데, 어느 쪽이든
  지금 규모(7일 활성 96명)로는 켜도 대부분 가려진다. 도시·지역·언어·브라우저·
  OS 는 값이 잘 나오지만 그건 GA에서 그대로 보면 되는 것들이라 옮길 이유가 없다.
- **페이지별 상세 쪼개기** — 페이지×기기/채널/신규재방문, 랜딩페이지 이탈률
  모두 API로 잘 나오는 걸 확인했다. 다만 GA 화면에서 바로 볼 수 있는 내용이라
  여기 옮겨 담을 값이 없다고 판단했다.

## 2. 레이아웃 겹침 — 검증 완료(2026-08-14)
예전엔 "표가 칸을 넘쳐 옆 구획을 덮는다"는 가설로만 방어해 뒀다(당시 브라우저로
열어 볼 수단이 없었다). 이번 박스 개편에서 Claude in Chrome으로 실제로 열어
500px·1400px 폭 모두 가로 스크롤 없음을 확인했다 — 가설이 아니라 실측이다.

방어 수단은 그대로 유효하다: 표는 `.scroll`(overflow-x: auto)로 감싸고,
`.module`에 `min-width: 0`, 캔버스·SVG에 `max-width: 100%`. 페이지 표는
숫자 칸에 `width: 1%`를 줘 이름 칸이 남는 폭을 다 가져가게 했다(이름과
숫자가 표 양 끝으로 벌어지던 것도 이걸로 잡았다).

박스 개편 중 실제로 찾은 건 겹침이 아니라 다른 종류의 레이아웃 버그 셋이었다
(모두 고침): `.dash-main`에 격자를 걸었더니 손자인 모듈이 격자에 못 들어간
것, 같은 줄 박스가 키를 맞추며(stretch) 짧은 박스에 빈 공간이 생긴 것,
인사이트의 `max-width: 62ch`가 박스 안에서 절반만 채운 것. 스킨을 새로
얹을 때 다시 겹치면 여기부터 볼 것.

## 3. 안 한 채로 남겨 둔 잔손질
스킨 작업과 섞으면 원인을 가리기 쉬워 일부러 뺐다. 스킨을 얹은 뒤에 판단할 것:
- **데이터가 오래돼도 티가 안 난다** — 워크플로우가 실패하면 옛 숫자가
  그대로 남고 화면은 아무 말도 하지 않는다. `meta.updatedAt` 이 이틀 이상
  지났으면 머리말에 한 줄.
- **Chart.js CDN 실패** — 못 불러오면 차트 자리가 빈 칸으로 남는다. 표는
  이미 옆에 있으니 안내 한 줄이면 된다.
- **순위 표에 비중 막대** — 어제 본 페이지·유입원은 숫자만 있어 크기 차가 늦게
  읽힌다. 칸 뒤에 옅은 막대를 깔면 순위가 먼저 보인다.
- **인사이트 문장의 숫자 강조** — CSS에 `.insights b` 스타일은 있는데 수집
  스크립트가 굵게 표시를 넣지 않아 실제로는 안 쓰인다. 문장을 그대로 이스케이프해
  넣고 있어서, 굵게 하려면 파이썬에서 텍스트와 강조 자리를 나눠 보내야 한다.

참여율·체류시간은 그래서 확정 구간(어제를 뺀 7일)에서만 보여준다. 유입원은
2026-08-18부터 다르게 푼다 — 그저께치를 다음 날 한 번 더 조회해 히스토리에
덮어쓴다(위 1번 "히스토리" 참조). 실측(2026-08-18, 최근 4일 대조)으로는
하루~이틀이면 충분했다.

실시간에 가까운 카운터를 원한다면 주기를 늘려야 하고, 그만큼 데이터 파일
자동 커밋도 늘어난다(3시간마다 = 하루 8건).

**로컬 세션과의 충돌**: 워크플로우가 origin에 매일 직접 커밋하는 동안 로컬
세션은 며칠 전 지점에서 기능을 쌓기 쉬워, `dashboard/data/*.js`에서만 머지
충돌이 반복됐다(2026-08-18 실제 발생). `.gitattributes`의 `merge=ours`로
이 파일들은 항상 로컬을 유지하고 충돌 표시 없이 넘어가도록 고쳤다 — 단
신선도를 비교하지 않으므로, 머지/푸시 전에 `ga4_dashboard.py`를 한 번
재실행해 로컬 데이터를 최신으로 만들어 두는 습관이 필수다. 클론마다
`git config merge.ours.driver true`를 로컬로 한 번 등록해야 실제로 동작한다
(`.gitattributes` 안 주석 참조).
